## 0. The operating rule, corrected

The rule that was in force was wrong:

```
/services/ query evidence unavailable  →  stop SEO
```

The correct rule:

```
/services/ query evidence unavailable
        →  do not finalise /services/ commercial intent
        →  continue every workstream that does not depend on it
```

One decision is quarantined. The project is not. Two tracks:

```
                    COZELOS SEO
                         │
             ┌───────────┴────────────┐
      /services/ track          everything else
             │                        │
   pre-F9 baseline held         KEEP MOVING
   re-pull 2026-09-08+          technical · architecture · entity
   then A–E decision            linking · local · GEO prep · evidence
```

Three levels of evidence, and only the third is short:

| Level | Question | State |
| --- | --- | --- |
| 1 — Business | What does Cozelos actually sell? | **Available now** |
| 2 — Site | What does the site currently express? | **Available now** |
| 3 — Search | What does Google associate with each URL? | **Weak for `/services/`; never tested elsewhere** |

Levels 1 and 2 should shape the architecture that Level 3 later validates. Working on them
is not guessing, provided nothing claims Level 3 backing it does not have.

From [gsc/00-pages.csv](./gsc/00-pages.csv), the whole property's click data:

| URL | Clicks | Impressions | CTR | Position | Page-filtered export? |
| --- | --- | --- | --- | --- | --- |
| `/` | **6** | 178 | 3.37% | 2.12 | ❌ never pulled |
| `/?page_id=158` | **6** | 131 | 4.58% | 13.63 | ❌ never pulled |
| `/?page_id=262` | 0 | 57 | 0% | 2.60 | ❌ |
| `/services/` | 0 | 53 | 0% | 7.13 | ✅ **pulled — zero query rows** |
| `/?page_id=866` | 0 | 46 | 0% | 2.74 | ❌ |
| `/portfolio/` · `/pricing/` · `/why-cozelos-data/` | 0 | 44 each | 0% | 1.43 each | ❌ (sitelink-shaped) |
| `www/services/` | 0 | 41 | 0% | 2.61 | — (retired by F9) |

**Every click this property has ever received belongs to `/` or `/?page_id=158`. Neither has
ever been page-filtered.** The project blocked itself on `/services/` — the highest-value
*commercial* URL, but the one with no clicks, a third of the homepage's impressions, and (as
now measured) no query rows at all.

This is not a criticism of the `/services/` gate, which was correct for the decision it
guarded. It is the observation that the gate was allowed to stand in for evidence-gathering
generally, and two better-populated URLs were never tested. Both are available today and
neither waits for September.
